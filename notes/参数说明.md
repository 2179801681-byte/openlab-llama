# `-n`、`-t`、`-ngl` 参数说明

## `-n`

`-n`（`--predict` / `--n-predict`）限制一次最多生成多少个新 token。
默认值 `-1` 表示不设专门的上限，生成到模型自然结束或达到上下文限制。
它只限制输出，不限制输入长度。

实验中也观察到了输出预算不足的情况：`-n 128` 时，模型的思考过程占满了预算，
正式回答还没开始就被截断。改为 `-n 200` 并关闭 reasoning 后得到完整回答。

## `-t`

`-t`（`--threads`）控制生成阶段使用的 CPU 线程数，不影响生成结果的正确性。
另有一个 `-tb`（`--threads-batch`），负责 prompt 批量预填充阶段。

把 `-t` 改为 1 后程序照常运行，但只有一个线程参与解码，生成速度会明显下降；
CPU 占用和功耗也会降低。推理主要受内存带宽限制，速度通常不会严格按线程数
成反比。

## `-ngl`

`-ngl`（`--gpu-layers` / `--n-gpu-layers`）指定最多有多少层模型权重放在显存中。
`0` 表示纯 CPU，数值越大，卸载到 GPU 的层越多。新版还接受 `auto` 和 `all`。

本次构建是纯 CPU 版本。设置 `-ngl 9999` 后，程序没有尝试分配显存，而是输出：

```text
warning: no usable GPU found, --gpu-layers option will be ignored
warning: one possible reason is that llama.cpp was compiled without GPU support
```

结果仍可正常生成，速度与纯 CPU 运行接近。

如果构建时启用了 CUDA 或 Vulkan，而指定层数需要的显存超过可用显存，
加载模型时会发生缓冲区分配失败，进程报错退出，不会自动忽略或退回 CPU。
这时应减小 `-ngl`，或者使用 `-ngl auto`。

另外，`-ngl` 超过模型实际层数不会让程序越界。源码会把有效卸载层数限制在
模型层数加一以内。
